项目概览

CoreTexDB 是一个面向 AI 应用的多模态向量数据库，使用 Rust 编写，提供向量检索、混合检索（BM25 + 向量 + RRF）、SQL 接口、分布式（2PC / Raft）、安全（TLS / AES-256-GCM / RBAC）、时序 / 地理 / 图谱等能力，并暴露 REST、gRPC、GraphQL、WebSocket 多种 API，同时提供 Python 客户端绑定。

本地快速开始

# 编译（默认特性：tokio/serde/compression/metrics） cargo build # 调试版 -> target/debug/coretex.exe cargo build --release # 发布版 -> target/release/coretex.exe # 启动服务（REST 默认 0.0.0.0:5000，默认关闭鉴权） ./target/release/coretex.exe server --host 0.0.0.0 --port 5000 # 健康检查 curl http://localhost:5000/health
本控制台为静态站点（部署于 CloudStudio）。调试台通过浏览器直接请求你配置的 CoreTexDB 地址；若实例未开放 CORS，请将请求改为同源或经由你自己的反向代理转发。

REST 接口参考

默认端口 5000。默认启动 不启用鉴权（CLI server 子命令不带 --auth 时）。/health、/api/auth/login、/api/auth/register、/raft/* 无需鉴权。

方法路径说明
GET/health健康检查，返回 {status,version}
POST/api/auth/login登录，body {username,password}
POST/api/auth/register注册（首用户免鉴权，其余需 admin token）
GET/api/collections列出所有集合
POST/api/collections创建集合，body {name,dimension,distance_metric?}
GET/api/collections/:name集合信息
DELETE/api/collections/:name删除集合
GET/api/collections/:name/stats集合统计
POST/api/collections/:name/vectors插入向量，body {vectors:[{id,vector,metadata?}]}
PUT/api/collections/:name/vectors更新向量
GET/api/collections/:name/vectors/:id获取单条向量
DELETE/api/collections/:name/vectors批量删除，body {ids:[]}
POST/api/collections/:name/search向量检索，body {vector,k,filter?}
POST/api/collections/:name/batch-search批量检索，body {queries:[[...]],k,filter?}
GET/api/collections/:name/count向量数量

部署说明

本页由 CloudStudio 静态托管，是 CoreTexDB 的云端控制台与文档入口。向量数据库服务本身是有状态的后端进程，需要运行在具备二进制的宿主（裸机 / 容器 / VM）上。下方给出两种生产部署方式。

方式一：Docker（推荐）

# 构建镜像（多阶段，产物为静态链接的 coretex 二进制） docker build -t coretexdb:1.1.0 . # 运行 docker run -d --name coretexdb -p 5000:5000 -p 50051:50051 -p 8080:8080 \ -v coretex_data:/app/data coretexdb:1.1.0 \ server --host 0.0.0.0 --port 5000 --grpc-port 50051 --ws-port 8080

方式二：裸机 / systemd

# 发布编译 cargo build --release # 后台运行（建议配合 systemd 或 supervisor 托管） nohup ./target/release/coretex server --host 0.0.0.0 --port 5000 > coretex.log 2>&1 &

启用鉴权：在 server 子命令加 --auth；限制速率：--rate-limit 600（每分钟请求数）。默认 enable_cors 在未配置白名单时不放行跨域，浏览器控制台跨域调用需自行在反向代理（Nginx / Caddy）上补 Access-Control-Allow-Origin。
